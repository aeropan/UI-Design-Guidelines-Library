# 暖杏奶油风设计规范 · v1.0.0

定位：温暖、清晰、克制、可解释的浅色 Web 界面。适合对话和知识产品，不把某个疾病、后端或公司平台写成通用规范。

## 1. 权威与范围

- 唯一数值源：`packages/theme/src/tokens.json`。CSS/JSON/JS/声明均由构建生成。
- 行为规则：本文件与 COMPONENTS.md。实际 DOM/交互示例：packages/docs/index.html、app.js。
- 只定义浅色；暗色需独立扩展，而非套用上一套规范。
- 不依赖 React、AntD、Gradio、图数据库或远程字体。保留目标项目技术栈。
- 医疗场景只复用展示模式：证据、风险、边界须由业务系统真实提供，不能把设计示例当成已验证诊疗结果。

## 2. 色彩角色

| 角色 | token | 值 | 使用 |
|---|---|---|---|
| 品牌强调 | color.accent | #B37560 | 小面积识别、装饰、非文本强调 |
| 核心操作 | color.primary | #9E5F4E | 小字号白字按钮、链接、焦点 |
| Hover / 深强调 | color.primary-hover | #6B5045 | 主操作hover、强调文字 |
| 浅强调 | color.primary-subtle | #FEFAF7 | 侧栏、轻选中背景 |
| 页面 / 次表面 | color.page / surface | #FDFCFA / #FCFBF9 | 页面与平面区域 |
| 卡片 / 输入 | color.card / input | #FFFFFF / #FEFEFE | 内容与编辑 |
| 主要 / 辅助文字 | color.text / text-secondary | #3E3836 / #6F6763 | 正文与说明 |
| 常规 / 柔边框 | color.border / border-soft | #EDE5DD / #F8F1EB | 结构与柔和边界 |

Primary 是暖棕色系，不能替换成第一套的靛蓝。中性表面占主导，日常界面品牌强调约8–10%，语义反馈少量使用；真实风险/错误提示优先保证可见，不能为满足比例隐藏信息。

Success/Warning/Danger/Info 各有 bg、border、主色、深文字色。文字用 `*-text`，不能把较浅的状态主色直接当正文。状态同时有文案/图标；不只用颜色表达。

图谱分类色（cause/process/evidence/outcome）与状态色分开命名；关系 polarity 使用 edge-positive/negative/neutral。颜色不自动赋予真实因果语义。置信度/依据充分度需说明业务定义，不把任意百分比当作诊断准确率。

原项目品牌色配白字约3.73:1；小字号操作使用已有hover色#9E5F4E，白字约5.00:1。原始色保留为accent；这是一项有记录的可访问性规范化，非对原页面的像素复刻。

## 3. 字体与文字层级

字体栈：PingFang SC → Microsoft YaHei → Noto Sans SC → 系统字体。不同操作系统命中字体不同，不承诺跨平台字形完全一致。等宽优先JetBrains Mono，未打包字体时回退ui-monospace/Consolas。不默认加载CDN字体。

| 角色 | 大小 / 行高 / 字重 | 用途 |
|---|---|---|
| display | 28 / 36 / 700 | 欢迎页或规范总标题 |
| h1 | 24 / 32 / 700 | 页面标题 |
| h2 | 20 / 28 / 600 | 区块标题 |
| h3 | 16 / 24 / 600 | 卡片、面板标题 |
| body | 15 / 24 / 400 | 对话正文、可读内容 |
| compact | 14 / 22 / 400 | 导航、字段、紧凑内容 |
| small | 13 / 20 / 400 | 辅助说明 |
| caption | 12 / 18 / 500 | 时间、标签、状态、代码注记 |

标题700是明确允许的display/h1变体；普通标题600。不采用旧文档“一律不超过600”与表格700并存的冲突规则。新实现最小12px；不继承原页面8–11px字样。文献标题可用18/26/600作为场景变体。

## 4. 尺寸、空间与响应式

布局基线4/8/12/16/20/24/32/40/48/64；组件内部10/14px、标签3/10px等有名例外可用，不能据此任意扩展页面栅格。圆角6（输入）、10（按钮）、12（卡片）、14（composer）、16（弹窗）、pill999。

- 侧栏240，折叠72；详情380，紧凑250。
- 1100及以下：侧栏固定缩略、文献单列、详情紧凑；折叠按钮显示不可用且aria-expanded=false，恢复宽屏后可手动切换。
- 920及以下：详情改为可关闭覆盖面板，不继续挤压正文。
- 内容参考最大1000，文献工作区最大1440；实际页面必须适配视口，不锁死桌面画布。
- 普通按钮38、小按钮32、图标按钮30；触摸环境目标至少44。
- 普通弹窗440，紧凑400，反馈560，展开画布最大1100；均受视口限制，不复制第一套420/480/640/900档位。

## 5. 表面与动效

允许极轻暖灰静态阴影xs；hover为sm，普通弹窗为modal，输入编辑器用composer阴影。资料条目默认透明/平面、无阴影，hover仅轻微背景变化。不能把所有内容都做成厚重卡片。

基本动效150ms；弹窗220ms；面板300ms；Tooltip延迟400ms。减少动态效果设置下关闭过渡/动画。原项目APNG/视频不属于规范必需项；静态内容就应完整传达状态。

## 6. 组件与状态

详细规则、实际类名和可用程度见 COMPONENTS.md。

- Button：primary/secondary/ghost/danger/disabled，hover/pressed/focus可见。
- Input：label不省略，placeholder不代替label；错误用aria-invalid并关联提示。
- Chat：用户与助手消息区分结构和对齐；正文支持换行；发送中可停止；中断与错误不能伪装成成功。
- Clarification：明确提示缺少什么，选项与自由输入并存；实际选项由业务决定。
- Trace：步骤、证据与回答分区；“进行中/完成/无依据/风险”需要不同文案，不得固定永远显示成功。
- Dialog：优先原生dialog或框架可访问组件；打开后聚焦、限制Tab在弹窗内、Esc关闭、关闭后返回触发点；危险确认不靠遮罩误点确认。
- Toast：状态提示，不阻断主任务；重要风险保留在页面内，不能只短暂闪现。
- Tooltip：悬停和键盘focus都能触发，Esc关闭；重要信息不可只放tooltip。
- Library：110px左右缩略图+标题/元数据/摘要/标签，两列；小屏单列；无结果与缺封面有占位。
- Graph：分类、关系、依据分开展示；可聚焦节点与详情。实例仅是HTML关系示意，不提供完整图谱布局引擎、2D/3D渲染库或后端。

## 7. 可访问性与验证

小字号普通文字至少4.5:1；大字是否适用3:1按实际字号和字重判断，不能把所有按钮文字归为“大字”。必要的非文本控件/图形目标3:1；装饰和不可用元素按其适用条件处理。

键盘顺序与视觉一致；不隐藏焦点；消息变化用适当live区域；发送处理中文输入法合成状态；对话内容作为文本渲染，不解析用户输入HTML。

验证覆盖：token产物一致、关键文字对比度、无未定义变量、导航折叠、对话发送/停止、搜索空态、弹窗焦点与Esc、详情面板尺寸、窄屏和reduced-motion。
